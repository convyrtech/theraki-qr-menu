**Главные пробелы:**
- Варёные КРАСНЫЕ раки: отсутствуют. Все целые раки (кадры 234-263) серо-зелёно-оливковые = живые/сырые, не отварные. Нужна студийная съёмка красных варёных раков (с клешнями) — это флагман главы 'Раки'.
- Жареные раки (золотистые, на пиве/в сливочно-чесночном): отдельной узнаваемой подачи нет. Сырые зелёные раки не годятся как 'жареные'.
- Камчатский краб СОЛО целиком (тело/панцирь на льду с бёр-нуазет): нет. Есть только фаланги/ноги краба в стеклянной чаше (122-131) и краб внутри блюд (паста/салат/хот-дог).
- Напитки целиком: чай и кофе (tea) — 0 фото; воды/соки/газировки/квас/морс (soft) — 0 фото; пиво (beer) — 0 фото. Три питьевые главы без единого кадра.
- Десерт THE RAKI (тирамису с жидким центром) на тарелке: не опознан; есть только упаковочные стаканчики с мороженым (264-282), которые не читаются как фирменная подача.
- Куриная лапша (прозрачный бульон) и второй/третий суп: не опознаны отдельно; уверенно виден лишь один жёлто-кремовый суп (16-22).
- Конкретные холодные закуски — бейби-картофель с килькой, хрустящие битые огурцы, черри+моцарелла: уверенной привязки нет (канапе 23-39 и брускетты 210-233 не разбираются по этим позициям).


## 2. Research — 3 угла


### Угол 1 — Навигация / IA (ex-Toast/Wolt продуктовый дизайнер)

**Главное:** Для премиум-раковарни на 390px стройте меню как ОДНУ скролл-страницу с секциями-категориями + узкая sticky-горизонтальная лента чипов (макс ~5 видимых: Краб / Раки / Креветки / Мидии / Напитки), которая по тапу делает anchor-jump к секции и сама прячется при скролле вниз / возвращается при скролле вверх (Smashing). Тап по блюду открывает ПОЛНОЭКРАННУЮ карточку (фото, граммовка, ₽/кг, добавить) — НЕ bottom-sheet (NN/G). Держите ~7-10 позиций в категории, один столбец, фото ~1200px, тап-зоны 48px. Отсутствие фото варёных раков/краба соло/напитков — это не дефект: премиум-заведения сознательно обходятся без фото (FSR); сделайте текстовые позиции единым осознанным стилем (не более двух визуальных стилей), и они читаются дорого, а не дёшево.


**Находки:**

**1. Sticky/anchored category navigation is the recommended way to escape an 'infinite vertical scroll' on a long mobile menu — let guests jump to a section instead of scrolling the whole list.**
   - _Доказательство:_ NN/G Guideline 15: 'Consider Sticky (or Partially Sticky) Menus for Long Pages' — persistent menu access at the viewport top avoids tedious scrolling to reach navigation controls. Sticky nav is 'a good feature, especially if the menus are frequently used and when you want to speed up navigation.'
   - _Источник:_ https://www.nngroup.com/articles/menu-design/ + https://support.toasttab.com search result summary

**2. A sticky/horizontal category bar must stay tiny: no more than ~5 visible items, because mobile vertical space is scarce and over-large sticky bars eat the screen.**
   - _Доказательство:_ Smashing Magazine: sticky bars 'can't have more than five items' due to mobile screen limitations; recommends 'partially persistent headers' that hide on scroll-down and reappear on scroll-up, with 300-400ms animation. Must set CSS scroll-padding so anchor jumps land below the sticky bar.
   - _Источник:_ https://www.smashingmagazine.com/2023/05/sticky-menus-ux-guidelines/

**3. For 4+ categories, the proven structure is one scrollable page with category sections + a sticky horizontal category strip that anchor-jumps, NOT a deep multi-level menu tree.**
   - _Доказательство:_ NN/G drill-down (Guideline 9) suits 'deep information structures'; but for a single product/category surface, drill-down 'should be avoided if you expect users to frequently move between levels.' A QR menu where guests bounce between Краб/Раки/Креветки favors single-page + anchor jumps over level-by-level drill-down.
   - _Источник:_ https://www.nngroup.com/articles/menu-design/ + https://lovable.dev (search result summary)

**4. The item-detail screen (photo + description + grams/options) should be a FULL screen/page, not a bottom sheet — bottom sheets are explicitly wrong for product-detail content.**
   - _Доказательство:_ NN/G: 'don't use a sheet to display an ecommerce product-detail page... a bottom sheet will break longstanding conventions of how users can navigate from page to page'; 'use bottom sheets only for short interactions' and avoid content where users 'spend significant time reviewing the information.'
   - _Источник:_ https://www.nngroup.com/articles/bottom-sheet/

**5. Keep ~7-10 items per category (some sources say 5-7 categories total) — fewer, well-grouped options reduce decision fatigue and actually push guests toward higher-priced items.**
   - _Доказательство:_ Menubly: 'aim for 7-10 items per category.' Altametrics cites Bournemouth University: customers are 'more confident... when menus have fewer items and are well-organized,' and 'when presented with fewer but clearly categorized options, diners are more likely to pick higher-priced items.' UpMenu: '5 to 7 menu categories' per Miller's Law.
   - _Источник:_ https://www.menubly.com/blog/common-menu-design-mistakes/ + https://altametrics.com/design-a-restaurant-menu/restaurant-menu-layout.html + https://www.upmenu.com/blog/restaurant-menu-examples/

**6. Premium/upscale venues typically forgo photos entirely — so the missing photos for варёные раки / краб соло / напитки are NOT a defect; text-only premium items read as upscale, not cheap.**
   - _Доказательство:_ FSR Magazine: 'upscale, expensive restaurants usually forgo photos on their menu entirely,' contrasted with fast-food showing imagery for every item; decision should align with 'the overall atmosphere you're trying to create.' Menubly: for an upscale approach consider 'illustrations or icons rather than photos.'
   - _Источник:_ https://www.fsrmagazine.com/feature/should-your-restaurants-menu-have-photos/ + https://www.menubly.com/blog/common-menu-design-mistakes/

**7. Visual consistency rule when mixing photo and no-photo items: never blend more than two styles; bad/uneven photos hurt more than no photo. Use one consistent treatment so text-only items look intentional.**
   - _Доказательство:_ Menu-design guidance: 'Keep consistency in style, never mixing more than two styles'; 'It's better to use no photos than bad photos'; 'There is nothing more frustrating than straining to see that some food does not have a photo.' Alternative: point to Instagram for previews instead of cramming all photos.
   - _Источник:_ https://www.menubly.com/blog/common-menu-design-mistakes/ (via search) + https://www.fsrmagazine.com/feature/should-your-restaurants-menu-have-photos/

**8. Group drinks/beverages as their own top-level branch with subfilters; mirror real eating flow for food (starters -> mains -> dessert).**
   - _Доказательство:_ Search summary (digital menu UX): 'For drinks, group by alcoholic and non alcoholic, then add subfilters like beer, wine, coffee, tea.' Menubly: organize 'a logical flow that aligns with how people typically eat—starting with appetizers, moving to main courses, and finishing with desserts,' then 'by protein type, cooking method.'
   - _Источник:_ https://spiltmilkwebdesign.com/mobile-ux-design-for-on-the-go-diners-expert-tips-for-cafes-in-2025/ (search summary) + https://www.menubly.com/blog/common-menu-design-mistakes/

**9. Mobile menu format rules: single-column list, sub-2s load, images ~1200px wide and compressed, tap targets >=48x48px, short names, allergen/price kept on one line.**
   - _Доказательство:_ Spilt Milk: 'Single-column lists are superior to columns or tabs'; tap zones 'at least 48x48 pixels'; target 'sub-2-second load times'. Search summary: 'a photo around 1200 pixels wide is enough for a mobile digital menu'; 'place allergy and dietary labels near the name so the icons do not push the price off screen.'
   - _Источник:_ https://spiltmilkwebdesign.com/mobile-ux-design-for-on-the-go-diners-expert-tips-for-cafes-in-2025/

**10. Guests skim fast — design for ~109 seconds of attention; the menu 'shouldn't feel like a website or require too many taps.' This argues for shallow navigation, not deep drill-downs.**
   - _Доказательство:_ Altametrics: customers spend 'an average of 109 seconds reading a menu,' so menus should avoid cramming per screen, stay 'swipe-friendly,' and not 'require too many taps.' Deloitte (cited): 60%+ of diners prefer a digital menu if it speeds ordering.
   - _Источник:_ https://altametrics.com/design-a-restaurant-menu/restaurant-menu-layout.html

**Примеры:**
- **Toast Online Ordering — menu hierarchy** — 3-4 level model: Menus (top-level, e.g. Food/Drinks/Bar) -> Menu Groups (Appetizers/Entrees/Desserts) -> Items -> Modifiers. Crucially, Toast's own Online Ordering & Mobile Order-and-Pay 'do not support subgroups' — sub-group items collapse into the parent group on the customer-facing surface. Lesson for a QR menu: keep customer-facing structure to TWO levels (category -> item), push any finer split into the item screen, not the navigation. (https://doc.toasttab.com/doc/platformguide/adminMenuHierarchy.html)
- **Smashing Magazine — partially-sticky header pattern** — Documents the 'partially persistent' header: the category bar hides on scroll-down (giving the menu its full width/height) and reappears on scroll-up when the guest wants to switch category, animated 300-400ms. Pairs a sticky strip with a table-of-contents + back-to-top fallback, and fixes anchor-jump offset with CSS scroll-padding. Directly applicable to a 390px raki menu. (https://www.smashingmagazine.com/2023/05/sticky-menus-ux-guidelines/)
- **NN/G — bottom sheet vs full-screen decision** — Defines the rule we should follow for tapping a dish: full-screen detail page for the crab/raki item (photo, grams, price-per-kg, add-to-order), reserving bottom sheets only for short one-shot interactions (e.g. a quick quantity/weight picker), because sheets break page-to-page navigation expectations. (https://www.nngroup.com/articles/bottom-sheet/)

**Анти-паттерны:**
- Infinite single 'вертикальная простыня' with no sticky category strip — guest must scroll past everything to reach Десерты; violates NN/G Guideline 15 and the 109-second attention budget (altametrics).
- Sticky/horizontal category bar with more than ~5 chips visible — Smashing Magazine caps sticky bars at 5 items; a 7-category strip will either wrap (eats height) or overflow off-screen.
- Putting the dish detail (photo + description + grams + add-to-order) in a bottom sheet — NN/G explicitly says do NOT use a sheet for product-detail content; use a full screen.
- Deep multi-level drill-down (category -> subgroup -> sub-subgroup -> item) on a QR menu — Toast itself disables subgroups on its customer ordering surface; drill-down is discouraged when guests hop between categories a lot (NN/G G9).
- Photographing only a few dishes with inconsistent quality and leaving others bare in a way that 'strains' the eye — better no photo than a bad/uneven one; never mix more than two visual styles (menubly).
- Treating the missing photos (варёные раки / краб соло / напитки) as a problem to paper over — for a premium venue, clean text-only premium items are the upscale norm (FSR), not a gap.
- Cramming long paragraphs and pushing price/allergen tags off the 390px line, or using >1200px uncompressed images that blow the sub-2s load budget (spiltmilk).


### Угол 2 — Визуал / Layout (премиум-гастро дизайнер)

**Главное:** Для премиум QR-раковарни на 390px перенимаем не 'сетку с фото на всё', а светлый редакционно-журнальный одноколоночный лейаут (cream+black, тело >=16px, описания в 1-2 строки): горизонтальные pill-категории сверху без гамбургера, 5-8 категорий, первые позиции в один скролл. Фото ставим ТОЛЬКО на топ/сигнатурные блюда единым курированным набором (один свет/фон/угол на категорию, один hero на блюдо) — смешанное меню 'часть с фото, часть текстом' это нормальный премиум-паттерн, который как раз закрывает дыры (варёные раки/краб-соло/напитки без фото). На категорию — один широкий full-bleed hero-кадр (как Canlis/The Ivy/Black Swan), а не россыпь превью. Цены — круглым числом цифрами без ₽ и копеек. 1-2 акцентные позиции на секцию белым пространством, не больше. И жёстко держим вес: фото <200KB, первый экран <2MB, контент за 2-3 сек — иначе тормоза убивают всё ощущение 'дорого'.


**Находки:**

**1. Премиум-сегмент визуально делится на два полярных подхода: 'Elegant Typography' (fine dining) — вообще БЕЗ фото, только красивый шрифт, одна колонка, щедрые поля; и 'Dark Mode' (бары/премиум-атмосфера) — тёмный фон, тёплый светлый текст, крупный кегль. Оба читаются как дорогие именно за счёт сдержанности, а не обилия картинок. 'Photo-Forward' (карточки с крупным фото в каждой) и 'Grid Layout' (многоколоночная сетка с превью) маркируются как casual/большие меню, НЕ как премиум.**
   - _Доказательство:_ Разбор 8 QR-шаблонов: '#3 Elegant Typography (Fine Dining) — Single column with generous margins, No photos no flashy elements, Serif or elegant sans-serif, sophistication through restraint, Premium? Yes'. '#5 Dark Mode (Bars) — Dark background, light text in warm tones, larger font sizes, Premium? Yes'. '#2 Photo-Forward (Casual Dining) — Card-based single column, prominent image slots, Premium? No'. '#6 Grid Layout (Large Menus 50+ items) — Multi-column collapsing to single, optional thumbnails, Premium? No'.
   - _Источник:_ https://menustack.app/blog/qr-code-menu-templates/

**2. Для QR-меню на телефоне правильный паттерн — ОДНА колонка, а не сетка: гость смотрит на 6-дюймовый экран. Навигация по категориям (горизонтальные pill-таблетки ИЛИ чёткие визуальные секции) должна быть первым, что видит гость — никаких гамбургер-меню. Категорий должно быть 5-8 максимум, первые блюда видны в пределах одного скролла.**
   - _Доказательство:_ 'Use a single-column layout since guests are viewing on a 6-inch phone screen, minimum 14px font'. Dineazi: 'five to eight categories maximum', 'Categories and first items visible within one scroll on a 6-inch phone', 'horizontal pill navigation or clear visual sections starting immediately — avoid hamburger menus', 'Category navigation should be the first thing a guest sees'.
   - _Источник:_ https://dineazi.com/resources/qr-menu-design-tips

**3. Фото в меню должны быть КУРИРОВАННЫМ единым набором, а не россыпью разных кадров. Главное правило — консистентность бьёт художественность: одно блюдо снято под одним углом, на одном фоне, при одном свете для всей категории. Один hero-кадр на блюдо. Это и есть граница между 'дорого' и 'дёшево': разнобойные кадры читаются как любительские, единый стиль — как премиум.**
   - _Доказательство:_ 'Your menu needs to look like one cohesive collection, not 50 random images'. 'Lock one light setup throughout the entire shoot'. 'Pick one surface (dark wood, white marble, slate) and use it for every shot'. 'Shoot all items in a category at the same angle — 45° for entrées, overhead for flat dishes, straight-on for drinks'. 'One hero shot per menu item'. Из поиска FoodShot: 'a merely good photograph that matches the rest of the menu beats an excellent picture that stands out'.
   - _Источник:_ https://foodshot.ai/blog/food-photography-restaurant-menus

**4. Фото значимо поднимает заказы, но переизбыток мелких превью в сетке обесценивает бренд. Решение для нашего кейса (фото есть НЕ на всё) — фото только на топ-позиции/высокомаржинальные, остальное текстом. Смешанное меню (часть с фото, часть без) — нормальный премиум-паттерн, а не дефект.**
   - _Доказательство:_ FoodShot: 'Online ordering conversions jump 25%+ with food photography vs text alone'; 'Overall sales increase 20-45% using professional-quality photography'; '82% of people will order a dish based purely on how it looks'. Дополнительно из поиска (NovaTab / Dineazi): 'too many can cheapen the feel; upscale restaurants often avoid pictures altogether'; 'Do not photograph everything — use images strategically on high-margin items, one consistent house style across your top ten dishes'.
   - _Источник:_ https://foodshot.ai/blog/food-photography-restaurant-menus

**5. Премиум-сигнал в цене: убрать символ валюты (₽/$) и копейки, оставить круглое число цифрами. Это и психология (снижает 'боль оплаты'), и визуальная чистота. Округлённые числа усиливают восприятие люкса; знак валюты заставляет тратить меньше.**
   - _Доказательство:_ Cornell Hospitality Report (Dr. Kimes): 'when prices were given with dollar signs, customers spent less than when no dollar signs appeared'; customers 'spent significantly more when the price was listed in numerals without dollar signs, as in 14.00 or 14, than when it included the word dollar'. Из поиска: 'rounded prices increase the perception of luxury and craftsmanship (Journal of Consumer Psychology)'; Cornell — '~8% more' без знака доллара.
   - _Источник:_ https://www.neurosciencemarketing.com/blog/articles/neuro-menus-and-restaurant-psychology.htm

**6. Премиум-рестораны в цифре строят экран как редакционный разворот / журнал: широкие hero-кадры на всю ширину (full-bleed), фото-навигация (картинка = вход в раздел), много воздуха, минимум визуального шума, лёгкая анимация для повествования вместо плотной сетки карточек. 'Дорого' = сдержанность + крупный визуал + чистая типографика, а не плотность.**
   - _Доказательство:_ eatapp: The Ivy — 'sleek and modern, stunning scrolling imagery, full-screen visual navigation'; The Black Swan Oldstead — 'designed to resemble a glossy food magazine, but fast-loading'; The Clove Club — 'minimalist, animation of a plant slowly grows, sophistication through restraint'. Общий паттерн: 'Hero imagery dominates above-the-fold, generous white space and clear typography, minimal navigation clutter'.
   - _Источник:_ https://restaurant.eatapp.co/blog/best-restaurant-website-designs

**7. Визуальная иерархия важнее украшений: выделять 1-2 'звёздные' позиции на секцию белым пространством/рамкой/чуть большим кеглем — не больше. Перегруженность секций = маркер бюджетного меню. Сигнатурные блюда подаются чуть крупнее, акцент применяется экономно.**
   - _Доказательство:_ altametrics (Trend #2): 'size variation and subtle borders rather than flashy graphics', 'emphasis applied sparingly (1-2 items per section maximum)', 'slightly larger fonts for signature dishes'. Trend #1: 'High-end menus use intentional negative space and limited item counts; budget menus often overcrowd sections'. 'Good menu layout can increase sales by up to 15%'.
   - _Источник:_ https://altametrics.com/design-a-restaurant-menu/restaurant-menu-layout.html

**8. Читаемость на телефоне — техническое требование премиума: тело текста минимум 16px на мобильном, высокий контраст (чёрный/тёмный текст на cream/off-white ИЛИ инверсия), описание блюда 1-2 строки максимум. Cream+black и тёплая палитра — классическое сочетание для люкс-морепродуктов.**
   - _Доказательство:_ Из поиска (supercode/dineazi): 'Minimum 16px body type on mobile with strong color contrast'; 'short descriptions, one to two lines on a mobile screen'. menustack #3: 'Dark text on cream/off-white or inverse'. Из поиска по seafood: 'soft cream and black palette that exudes luxury, clean professional layouts; hero images showcasing signature dishes'.
   - _Источник:_ https://menustack.app/blog/qr-code-menu-templates/

**9. Производительность — часть премиум-восприятия: страница должна отдавать первый контент за 2-3 сек на 4G, вес первого экрана под 1.5-2MB, каждое фото сжато под 200KB (полноразмерное фото с телефона 3-8MB — это в 15-40 раз больше нужного). Медленное тяжёлое меню убивает ощущение качества.**
   - _Доказательство:_ Dineazi: 'under 200KB per image (Squoosh, TinyPNG)'; 'A full-resolution phone photo is typically 3-8MB. That is 15x to 40x what it needs to be'; 'First content within two to three seconds on a 4G connection'; 'Keep under 1.5-2MB for the first view'. FoodShot: 'Website/digital 1200x800px, compress under 200KB, use WebP or JPEG'.
   - _Источник:_ https://dineazi.com/resources/qr-menu-design-tips

**Анти-паттерны:**
- Сетка 2 колонки с фото-превью в каждой ячейке на мобильном — маркируется как casual/большое меню ('Grid Layout', 'Photo-Forward' в разборе menustack = Premium? No). Для премиума на 390px нужна ОДНА колонка, не сетка.
- Фото на каждое блюдо подряд мелкими карточками: переизбыток превью обесценивает бренд ('too many can cheapen the feel'; '15 images as small thumbnail on a phone wont grab attention'). Фото — только на топ/маржинальные позиции, остальное текстом.
- Разнобойные фото (разный угол/свет/фон/кадрирование) — читаются как любительские. Нарушает правило 'one cohesive collection, not 50 random images' и убивает премиум-восприятие сильнее, чем отсутствие фото.
- Гамбургер-меню для навигации по категориям ('avoid hamburger menus' — Dineazi). Категории должны быть видны сразу: горизонтальные pill-таблетки или явные секции.
- Знак валюты (₽) и копейки в цене + некруглые числа — повышают 'боль оплаты' и снижают восприятие люкса (Cornell: со знаком тратят меньше; round prices = +perception of luxury).
- Перегруженные секции, мелкий кегль (<16px тела на мобильном), низкий контраст, описания длиннее 1-2 строк — маркеры бюджетного меню ('budget menus overcrowd sections').
- Больше 5-8 категорий и первые позиции, не влезающие в один скролл на 6-дюймовом экране — decision fatigue, нарушение QR-паттерна.
- Тяжёлые несжатые фото (3-8MB) и страница >2MB на первый экран: первый контент должен прийти за 2-3 сек на 4G, иначе медленная загрузка убивает ощущение премиума.


### Угол 3 — Критик (почему выглядит дёшево)

**Главное:** Главное, что перенять: меню выглядит дёшево не из-за 'некрасивых' элементов, а из-за ОТСУТСТВИЯ системы — иерархии, воздуха и консистентности. Внедрить три вещи. (1) Жёсткая типо-иерархия + воздух: 3 уровня шрифта (секция 18-20 / название 14-16 жирный / описание 11-12, межстрочный 1.5x), макс 2 гарнитуры, 40-50% белого, контраст ≥3:1 тёмным по светлому — это сразу убирает вид 'сломанного HTML'. (2) Фото как единый каталог, а не россыпь: один свет, один ракурс на категорию, белый студийный фон (наш кейс — правильный), единый пресет; смешивать фото и текст-онли МОЖНО (варёные раки/краб соло/напитки остаются без фото без потери премиума), но все имеющиеся фото обязаны быть стилистически идентичны. (3) Резать 390px-простыню: sticky bottom-nav или плитки/якоря категорий (Раки/Краб/Креветки/Мидии/Напитки), ≤5 пунктов, scroll-padding под липкую шапку. Эталон палитры и подачи — Nobu/Le Bernardin/Cosme: сдержанная палитра (чёрный/белый + один акцент), один сильный кадр флагмана вместо фото на каждой строке, минимум навигации, full-bleed фото.


**Находки:**

**1. Главная причина «дешёвого» вида цифрового меню — нулевая визуальная иерархия: единый размер текста превращает экран в «стену неразличимого текста». Лекарство — три размера шрифта: секции 18-20pt, названия блюд 14-16pt (жирный, на 2-3pt крупнее), описания 11-12pt, межстрочный 1.5x.**
   - _Доказательство:_ Kodo: 'Wall of undifferentiated text without size variation' назван прямым анти-паттерном; правило — section headers 18-20pt, dish names 14-16pt 'bold and 2-3pt larger than descriptions', descriptions 11-12pt, '1.5x line height'. Lisi: 'Headlines should be largest and boldest', line spacing '1.2-1.5x the font size'.
   - _Источник:_ https://usekodo.ai/guides/50-restaurant-menu-design-ideas-2026 ; https://blog.lisi.menu/colors-and-typography-for-menu-design/

**2. «Дорогое» меню держит 40-50% воздуха; теснота (cramped spacing) читается мозгом как низкое качество производства и снижает готовность платить. Это не косметика — плотная сетка прямо удешевляет бренд.**
   - _Доказательство:_ Kodo: 'Aim for 40-50% white space on each page'; анти-паттерн 'Cramped spacing that signals low-quality production'. Vigor: 'Crowded menus overwhelm guests. Clean spacing improves readability and enhances perceived quality' — повышает воспринимаемое качество и переносимость цены.
   - _Источник:_ https://usekodo.ai/guides/50-restaurant-menu-design-ideas-2026 ; https://vigorbranding.com/visual-hierarchy-and-menu-callouts-using-icons-boxes-and-layout-tricks-to-guide-choices/

**3. Слабая типографика «из 2010-х» = много конкурирующих шрифтов + декоративный/скриптовый шрифт в теле текста + низкий контраст (серый по белому). Премиум-правило: не более 2 гарнитур (1 акцентная для заголовков, 1 чистая для текста), контраст минимум 3:1, тёмный текст на светлом фоне.**
   - _Доказательство:_ Lisi прямо перечисляет cheap-сигналы: 'Multiple competing fonts', 'hard-to-read script fonts' для описаний, 'similar colors for text and background (like light gray on white)'; правило — 'Never use more than 3 font styles', 'Recommended: 2 fonts max', 'Minimum 3:1 contrast ratio', 'Dark text on a light background is the easiest to read'.
   - _Источник:_ https://blog.lisi.menu/colors-and-typography-for-menu-design/

**4. Неравномерное использование фото — один из главных удешевляющих факторов. Профессиональное меню = не 'одно красивое фото', а каталог из десятков, которые 'выглядят как принадлежащие друг другу': один источник света, один основной ракурс на категорию, максимум один-два фона, единый пресет обработки. 'Разнообразие — враг'.**
   - _Доказательство:_ FoodShot: 'It's about taking fifty that look like they belong together'; 'Variety is the enemy'; пять заблокированных параметров — 'Pick one light source... for every plate', 'Each item category gets one primary angle. Don't switch mid-menu', 'Two backgrounds is the maximum... One is better', 'Build one editing preset. Apply it to every photo'.
   - _Источник:_ https://foodshot.ai/blog/menu-photography-guide

**5. Можно НЕ снимать каждое блюдо (это решает нашу проблему с варёными раками/крабом соло/напитками), но при смешивании фото и текст-онли позиции все фото обязаны держать единый стиль, свет, фон и обработку — иначе разнобой 'путает' гостя. Слишком много фото, наоборот, создаёт congestion и удешевляет.**
   - _Доказательство:_ Поиск-сводка по FoodShot/нескольким источникам: 'you don't need to photograph every item... photograph the high-profit items or innovative dishes', НО 'If you do use a mix of photos and text-only items, ensure that all photographed items follow the same consistent style, lighting, background, and editing'; 'too many images on the menu run the risk of making it look too congested'.
   - _Источник:_ https://foodshot.ai/blog/menu-photography-guide ; https://www.ravikantphotography.com/the-ultimate-guide-to-food-photography-for-restaurants-menus-2026-edition/

**6. Фото-фон должен быть 'невидимым', а герой-ингредиент — однозначным за 1-2 секунды взгляда. Это валидирует наш белый студийный фон: для премиум-морепродуктов чистый нейтральный фон + один источник мягкого света = редакционный, не любительский вид.**
   - _Доказательство:_ FoodShot: 'The background's job is to be invisible'; 'A diner glances at a menu picture for one to two seconds. The hero ingredient needs to be unambiguous'; 'Move everything off the table except what's part of the plate'. Ravikant: согласованность фона 'enhances brand identity', варианты — 'marble surfaces, matte black backgrounds, linen textures', выбрать ОДИН и держать по всему меню.
   - _Источник:_ https://foodshot.ai/blog/menu-photography-guide ; https://www.ravikantphotography.com/the-ultimate-guide-to-food-photography-for-restaurants-menus-2026-edition/

**7. Премиум-почерк fine dining 2026 единообразен у топовых ресторанов: full-bleed фото, сдержанная палитра (чёрный/белый + один акцент), редакционная типографика, минимум навигации. ЧБ-фотография по всему сайту 'communicates luxury'. Это прямой ориентир для премиум-раковарни.**
   - _Доказательство:_ RichMenu: fine dining = 'full-bleed photography, restrained color palettes (often black, white, and one accent), editorial typography, minimal navigation', ощущение 'unhurried, curated'. StartDesigns по конкретным ресторанам: Nobu — 'Black-and-white photography throughout communicates luxury'; Le Bernardin — 'Dark backgrounds with strategically placed light elements... understated elegance'; Cosme — 'radically minimal homepage with logo, one image, navigation'.
   - _Источник:_ https://richmenu.io/top-restaurant-website-design/ ; https://www.startdesigns.com/blog/best-restaurant-websites/

**8. Вертикальная 'простыня' на мобильном без навигации = scroll fatigue. На экране 390px меню надо резать на секции с persistent/sticky навигацией (≤5 пунктов) или аккордеонами, а якоря — с scroll-padding, чтобы липкая шапка не перекрывала цель.**
   - _Доказательство:_ Smashing: sticky-навигация оправдана когда 'users navigate between different views on a page a lot and stay on the page' (длинные страницы); ограничение 'can't have more than five items in the sticky bar'; для тесноты 'show the menu as an accordion instead... especially on mobile'; якоря — 'account for the sticky bar with the scroll-padding property in CSS'.
   - _Источник:_ https://www.smashingmagazine.com/2023/05/sticky-menus-ux-guidelines/

**9. PDF-меню и 'шаблон с воткнутым логотипом' — корневая причина, почему QR-меню выглядят как ценник/демка. 95%+ сканов — с телефона, поэтому база должна быть mobile-first: одна колонка, крупные тап-таргеты, читаемость без зума, загрузка < 2-3 сек.**
   - _Доказательство:_ Сводка TableQR/FineDine: 'every QR code menu platform gives you... a template with your logo dropped in', результат 'looks like a text-based price list'; 'Over 95% of QR menu scans happen on phones... built mobile-first: single-column layouts, large touch targets, and text that's readable without pinching or zooming'; '> 2-3 seconds to load, a lot of people will give up'.
   - _Источник:_ https://tableqr.co/blog/top-7-digital-menu-systems-for-restaurants/ ; https://www.finedinemenu.com/en/blog/the-complete-qr-menu-guide-for-restaurants-everything-you-need-to-know-in-2026/

**10. Боксы/шейдинг и иконки направляют взгляд к маржинальным позициям, но только при сдержанности — переизбыток иконок 'захламляет и размывает' эффект. Для премиум-раковарни: выделять флагман (краб/раки) боксом, иконки (острое/фирменное) дозированно.**
   - _Доказательство:_ Vigor: 'Boxed items attract attention first' — выделять бестселлеры/премиум-апгрейды; иконки — 'chef's hat for signature, chili pepper for spicy', но 'The key is restraint. Too many icons clutter the page and dilute impact'; анти-паттерн 'Long, unbroken item lists without section breaks'.
   - _Источник:_ https://vigorbranding.com/visual-hierarchy-and-menu-callouts-using-icons-boxes-and-layout-tricks-to-guide-choices/

**Примеры:**

**Анти-паттерны:**
- Стена недифференцированного текста: единый размер шрифта без иерархии секция/название/описание — мозг читает это как ценник из 2010-х, не как меню ресторана (Kodo).
- Теснота (cramped spacing) и < 40-50% воздуха: плотная верстка напрямую сигналит 'low-quality production' и снижает готовность платить (Kodo, Vigor).
- Много конкурирующих шрифтов и скриптовый/декоративный шрифт в теле текста: профессиональный максимум — 2 гарнитуры (Lisi).
- Низкий контраст текст/фон (серый по белому, < 3:1): дешево и нечитаемо в зальном освещении (Lisi).
- Неравномерные/разнобойные фото: разный свет, ракурс, фон или обработка между блюдами 'путают' гостя — 'Variety is the enemy' (FoodShot).
- Сток-фотографии вместо реальных снятых блюд — мгновенный признак шаблона/дешевизны (RichMenu, StartDesigns).
- Перегруз фото: слишком много картинок создает congestion и удешевляет так же, как и нулевая иерархия (Ravikant/сводка).
- Загромождённый кадр: лишние предметы на столе, 'видимый' фон — фон должен быть невидимым, герой-ингредиент однозначен за 1-2 сек (FoodShot).
- PDF-меню и 'шаблон с воткнутым логотипом': превращает меню в текстовый ценник, не в современную страницу (TableQR, FineDine).
- Длинная одноколоночная 'простыня' на мобильном без секционной навигации/якорей/аккордеонов — scroll fatigue (Smashing).
- Десктоп-first подход при 95%+ сканов с телефона: мелкий текст, требующий зума, маленькие тап-таргеты (TableQR).
- Переизбыток иконок: 'clutter the page and dilute impact' — иконки только дозированно и осмысленно (Vigor).

## 1. Прямой ответ владельцу: как реально устроены диджитал-меню топ-ресторанов 2026

**Топовые меню — это НЕ «лента карточек с фото на каждое блюдо». Это редакционный разворот: одна колонка, много воздуха, фото только на флагманы, остальное — чистая типографика.**

- Nobu, Le Bernardin, Cosme строят экран как глянцевый журнал: full-bleed фото флагмана + сдержанная палитра (чёрный/белый + один акцент) + редакционная типографика + минимум навигации. *(kept: richmenu.io «full-bleed photography, restrained color palettes (often black, white, and one accent), editorial typography, minimal navigation»; startdesigns Nobu/Le Bernardin/Cosme).*
- В классификации QR-шаблонов **«Photo-Forward» (карточка с фото в каждой ячейке) и «Grid» прямо помечены `Premium? No`**. Премиум — это «Elegant Typography» (без фото, одна колонка, поля) и «Dark Mode». *(kept: menustack.app — #2/#6 = не премиум, #3/#5 = премиум).*
- **Отсутствие фото — не дефект.** Дорогие заведения сознательно обходятся без фото; текстовая позиция читается дорого, а не дёшево. *(kept: fsrmagazine «upscale, expensive restaurants usually forgo photos on their menu entirely»).*
- Меню «дёшево» не из-за некрасивых элементов, а из-за **отсутствия системы**: нет иерархии шрифта, нет воздуха, фото разнокалиберные. *(kept: usekodo «40-50% white space»; lisi «≤2 fonts, 3:1 contrast»; foodshot «one cohesive collection, not 50 random images»).*

**Почему наша «простыня карточек» = устаревший/дешёвый паттерн:**
1. Фото на одних главах + слипшийся текст-список на других = **разнобой стилей внутри одной ленты** — главный сигнал «любительского». *(kept: foodshot «Variety is the enemy»).*
2. 16 глав подряд без рабочей секционной навигации = scroll fatigue, гость не доходит до напитков. *(kept: nngroup Guideline 15; altametrics — бюджет внимания ~109 сек).*
3. Карточка-в-каждой-ячейке сама по себе маркирует casual, не премиум *(kept: menustack)*.

## 2. Структура страницы под НАШИ данные

**Решение: ОДНА скролл-страница (single scroll), НЕ отдельные экраны-категории.** Гость на QR прыгает между «Краб / Креветки / Пиво» — для этого single page + anchor-jump лучше, чем drill-down по экранам. *(kept: nngroup — drill-down не для частых переходов между уровнями; Toast отключает сабгруппы на клиентской витрине → держим 2 уровня: категория → блюдо).*

Но **внутри** страница должна перестать быть однородной простынёй. Вводим **три уровня подачи главы** по принципу «фото есть / нет»:

### Tier A — Флагман с фото (full-bleed hero)
Главы, где у нас есть сильный студийный кадр и есть «звезда»: **Краб (фаланги на льду), Креветки (красные «солнышком»), Мидии, Вонголе, Паста/Основные, Горячее/хот-дог.**
→ Один широкий full-bleed hero-кадр на главу + 1 акцентная позиция крупно, остальные позиции главы — компактным списком под ним. *(kept: eatapp Canlis/Ivy — один сильный hero важнее россыпи превью; altametrics — 1-2 акцента на секцию, не больше).*

### Tier B — Текстовая глава, оформленная как премиум (БЕЗ фото)
Главы без фото или со слабым материалом: **Напитки, Пиво, Чай/кофе, Соусы, Салаты, Закуски, Гарниры, Супы (второй/третий).**
→ Это НЕ «слипшийся список». Это **«Elegant Typography»-блок**: одна колонка, 40-50% воздуха, жёсткая 3-уровневая иерархия шрифта, золотой акцент-разделитель. Выглядит как винная карта, а не как сломанный `<ul>`. *(kept: menustack #3; usekodo «40-50% white space» + «18-20 / 14-16 bold / 11-12, line-height 1.5»; lisi).*

### Tier C — Раки (наш существующий тёмный разворот)
Доска «размер → ₽/кг» + стили варки/обжарки. Оставить как есть — это сильный, уже работающий приём. **Важно:** у нас НЕТ фото варёных красных раков и жареных раков (инвентарь: все целые раки сырые/зелёные). Значит Раки **обязаны** оставаться текстово-гравюрными — и это правильно, а не вынужденно. *(kept: fsrmagazine — текст-онли это премиум-норма).*

**Что делать с главами без фото, чтобы не было простыни (конкретно):**
- **Пиво (7 позиций)** → двухуровневый список «название (16pt bold) + страна/стиль тонким mono» + цена цифрами. Воздух между позициями 20-24px. Золотой волосок-разделитель между брендами.
- **Напитки/Чай (длинные)** → сгруппировать визуальными под-подзаголовками (Воды / Соки / Газировки / Морс-квас) внутри одной главы — это снимает ощущение «стены». Подзаголовок 14pt mono uppercase золотом.
- **Соусы / Гарниры (короткие, по 2-4)** → компактная двухколоночная строка «название … цена» (это единственное место, где 2 колонки уместны — короткие однострочники).

| **Десерты** | desserts |

**Поведение бара:** partially-sticky — прячется при скролле вниз, возвращается при скролле вверх, анимация 300-400ms, scroll-padding-top под высоту бара, чтобы якорь не уезжал под шапку. *(kept verbatim: smashing).*

`ChapterNav` у нас уже есть — переписываем items на 5 групп вместо 16, добавляем scroll-padding в CSS.

## 6. Пошаговый план: чтобы перестало быть «демкой»

**Шаг 1 — Убить разнобой фонов (1 действие, максимальный эффект).**
Свести всё меню к ОДНОМУ светлому кремовому фону + один тёмный акцент (Раки/интро). Убрать чередование `MusselsDark`/`VongoleLight`. Это мгновенно снимает «сломанность» — глаз перестаёт спотыкаться. *(kept: foodshot — единый фон важнее всего).*

**Шаг 2 — Переписать навигацию на 5 групп-чипов + scroll-padding.**
16 чипов → 5 надкатегорий (см. §3). Partially-sticky, 300-400ms. Без этого 16 глав = scroll fatigue. *(kept: smashing, dineazi).*

**Шаг 3 — Ввести Tier-B типографический блок для всех текстовых глав.**
Один компонент `TextChapter`: 3 уровня шрифта (секция 18-20 / имя 14-16 bold / описание 11-12, line-height 1.5), воздух 40-50%, золотой волосок-разделитель. Заменить им `CompactRow`-простыню в Напитках/Пиве/Чае/Салатах/Закусках/Супах/Гарнирах/Соусах. **Это убирает «сломанный HTML».** *(kept verbatim: usekodo, lisi).*

**Шаг 4 — Распространить full-bleed hero на ВСЕ главы, где есть хорошее фото.**
По инвентарю добавить hero к Паста/Основные (кадры 86-100), Горячее/хот-дог (101-119), оставить Краб/Креветки. Один hero на главу, не карточка-в-ячейке. *(kept: eatapp, altametrics 1-2 акцента).*

**Шаг 5 — Полноэкранная карточка блюда вместо bottom-sheet.**
Если деталь блюда сейчас в sheet (`SheetProvider`) — для блюд с описанием/составом/граммовкой перевести на полный экран. *(kept verbatim: nngroup bottom-sheet).*

**Шаг 6 — Цены и вес-бюджет (полировка).**
Цены уже голыми цифрами (`formatNumber`) — хорошо, держать без ₽ и копеек *(kept: neurosciencemarketing/Cornell)*. Сжать все фото <200KB, первый экран <2MB, контент за 2-3 сек на 4G — иначе тормоза убивают «дорого». *(kept verbatim: dineazi, foodshot 1200×800/WebP)*.

**Порядок по эффекту на «не-демка»:** Шаг 1 (единый фон) → Шаг 3 (типо-блок вместо простыни) → Шаг 2 (нав на 5 групп) — эти три закрывают ядро жалобы владельца. Шаги 4-6 — премиум-полировка после.

Фото при этом нужны ТОЛЬКО на 5-6 флагманов единым стилем; напитки/пиво/чай/раки остаются текстом — и это правильный премиум, а не дыра.
