## 4. Протокол `/loop` (как работать каждой итерацией)

1. Прочитать этот файл. Взять **первую невыполненную** `- [ ]` задачу по порядку.
2. Прочитать связанные источники из §2 перед правкой. Менять минимум, без посторонних рефакторов.
3. Реализовать одну атомарную задачу.
4. Проверить: `tsc`/`eslint` чисто **и** пикселями 390×844 (chrome-devtools/playwright). Для визуальных фаз — `/visual-qa`.
5. Отметить задачу `- [x]` в этом файле, закоммитить атомарно (`feat(menu): …`) на ветке `feat/site-aligned-menu`.
6. Повторить.

**СТОП-условия (выйти из цикла и вернуть управление владельцу):**
- все задачи `- [x]`; ИЛИ
- упёрлись в ввод владельца: подтверждение фото-сопоставления (G4), решение по спорному визуалу, недостающие фото-заглушки; ИЛИ
- `/visual-qa` красный и причина не правится за итерацию — описать и спросить.

**Не делать без владельца:** окончательная привязка фото, мерж ветки, смена `MENU_URL`/деплой, добавление контента не из дока.
