# ФИНАЛЬНАЯ UX-РАСКЛАДКА QR-МЕНЮ THE RAKI

> База — Концепт 1 (судья: 43/43, победитель), привиты grafts из К2/К3. Всё сверено по исходникам: `chapter-nav.tsx`, `wheel/page.tsx`, `proto-c`, cutout-набор. Cream доминирует, Marine Dark/золото — только акцент-куски.

## 1. ИТОГОВЫЙ ПАТТЕРН НАВИГАЦИИ

**Три яруса, каждый знает своё место:**

| Ярус | Что | Где | Роль |
|---|---|---|---|
| Верх | Компактный masthead «МЕНЮ / The Raki» + имя активной категории | sticky top, сжимается при скролле | контекст «ты здесь» |
| Центр | Вертикальная фото-лента блюд (cutout 4:3 + Cormorant-имя + ₽ + описание, асимметрия) | основной скролл-поток | ОСНОВНОЙ канал скана, самый быстрый |
| Низ | «Деревянная доска» — горизонтальная лента 16 категорий + якорная кнопка-колесо «Обзор» слева | sticky bottom, в thumb-zone | навигация по главам + вход в фишку |

**Почему так (опора на судью):**
- **Категории внизу, не вверху** — буквально реализует набросок владельца (matchSketch 9) и кладёт навигацию под большой палец (сценарий «стол, одна рука, 100 секунд»). Технически это перенос `ChapterNav` top→bottom: инверсия `probe` в scroll-spy + знак `offset` в `jump()`. Контейнерная правка, движок scroll-spy/jump/auto-center переиспользуется 1:1.
- **Колесо — НЕ навигация**, а вторичный обзорный оверлей по кнопке (wheelFit 9, scanSpeed 9). Судья отдельно срезал К2 за то, что там колесо стало основным навигатором и спрятало быстрый путь за свайпом. У нас быстрый путь (тап доски) всегда на виду, колесо не на критическом пути к блюду.
- **Колесо переиспользует `/wheel` почти as-is** как полноэкранный оверлей (feasibility 9) — против дорогого морфа кромки (К2) или переписывания `geom()` под компактный контейнер (К3).

**Привитые grafts (закрывают оба главных con'а К1):**
1. **Компактный сжимающийся masthead** (из К3) — решает «masthead+доска съедают вертикаль», фото-карточка помещается над доской на SE.
2. **Морф-раскрытие колеса ИЗ кнопки** (мягкая форма К2) — scale/shared-layout от кнопки к оверлею вместо плоского fade. Award-момент без риска «не нашли свайп».
3. **Золотой хват-подсказка на кнопке «Обзор»** один раз за сессию (из К2) — discoverability фишки.
4. **Опциональная 0.9с «заставка главы»** при тапе категории (из К3) — даёт колесу вторую роль-ориентир «ты в Крабе», СТРОГО по тапу, гасится любым касанием, не показывается при scroll-spy, `prefers-reduced-motion` → мгновенный jump.

## 2. ПОТОК ЭКРАНОВ ПО ШАГАМ

1. **QR → Интро-проявка** (1 раз/сессию, флаг в `sessionStorage`): тёмный Marine-экран → чернильные кляксы Роршаха разъедают надпись → проявляется кремовое меню. Компонент `Intro` сохраняем без изменений.
2. **Приземление:** сверху компактный masthead, под ним сразу первая карточка главы «Раки». Доска снизу уже под пальцем, активная дощечка «Раки» подсвечена золотом + авто-центрирована. Ноль обязательных жестов до контента.
3. **Скан-режим (90% времени):** гость скроллит вертикальную фото-ленту. Scroll-spy подсвечивает и авто-центрирует активную дощечку внизу. Masthead сжимается (имя категории остаётся).
4. **Прыжок по категории:** тап дощечки → smooth `jump()` к главе. Опционально (если не reduced-motion и явный тап) — 0.9с заставка-колесо «ты в Крабе», тает → список уже на первом блюде главы.
5. **Деталь блюда:** тап по карточке → раскрытие в bottom-sheet (full-описание + состав). CTA «в корзину» НЕТ — онлайн-заказа нет, гость называет блюдо официанту. Закрытие — свайп вниз / крестик, возврат в список на то же место.
6. **Обзор-колесо (опция):** тап кнопки «◴ Обзор» на левом якоре доски → морф в полноэкранный оверлей-колесо (`/wheel` as-is). Гость крутит дугу скроллом/драгом, центр-фокус крупнее, snap.
7. **Выход из колеса:** тап фокус-блюда → «Подробнее» (деталь) или «В списке» (оверлей закрывается, список скроллит к блюду). Крестик/свайп-вниз → возврат ровно туда, где был.

## 4. РОЛЬ И МЕСТО КОЛЕСА (конкретно)

- **Тип:** НЕ постоянный экран. Полноэкранный **оверлей по кнопке** «◴ Обзор» на левом якоре доски, визуально отделён разделителем от ленты категорий (чтобы не читался как 17-я категория).
- **Две честные роли:**
  1. **Playful-витрина / портфолио-актив** — гостю, которому скучно листать, даёт покрутить блюда по дуге (медленное, впечатляющее).
  2. **Кросс-категорийный «обзор лиц»** — топ-блюда/новинки вырезанными, фокус-снап = крупный кадр.
- **Опционально вторая ипостась** — 0.9с **заставка главы** при тапе категории (graft К3): тот же движок, мини-режим-ориентир. Строго по тапу, не при scroll-spy, гасится касанием, reduced-motion → выкл.
- **Не конкурирует со списком:** колесо медленное/впечатляющее, список быстрый/знакомый. Выход из колеса ВСЕГДА возвращает в быстрый скан-список.
- **Реализационная привязка:** `/wheel` (`rot/vel/snap`, фокус-логика, `geom()` на vw/vh) переезжает в оверлей-контейнер **полноэкранно as-is** — самый дешёвый порт. Слушатели сейчас на `railRef.parentElement.parentElement` — при переезде в оверлей этот предок сохраняем.
- **Контент колеса = БЛЮДА-лица, не 16 категорий.** Критично: cutout есть на ~6 категориях. 16 узлов-категорий на дуге (как хотел К2) с 6 фото выглядят сломанно. Колесо показывает ~7 топ-cutout-блюд (как уже в `DISHES`) — деградирует мягко.

## 5. ИЗ НАБРОСКА ВЛАДЕЛЬЦА: ЧТО БЕРЁМ / ЧТО УЛУЧШАЕМ

**Берём буквально:**
- Вертикальный фото-список блюд (фото/описание/цена, асимметрично) = основной контент. ✅
- Категории = горизонтальная лента СНИЗУ на «деревянных досках», прокручиваемая как таб-бар. ✅
- Сверху «МЕНЮ». ✅ (но компактно)

**Улучшаем:**
- **Гигант «МЕНЮ» → компактный сжимающийся masthead** (graft К3). Без сжатия masthead+доска съедают вертикаль, карточка не помещается над доской на SE. Освобождаем экран для блюд.
- **16 досок с фото нереалистичны** (cutout только на ~6). Вводим **два вида дощечки**: cutout-«лицо» там, где фото есть; **гравюрный значок + сериф-ярлык на cream-доске** для остальных 10. Лента однородна, не полупустая.
- **«Деревянную» текстуру держим графичной/cutout**, без буквального дерева во всю кромку — иначе «тёплый шум» против чистого cream (нарушение «most pixels cream»). Доска — cream-край с тонкой Marine-полосой, активная дощечка золотом.
- **Колесо из наброска не выпадает** — владелец спрашивал «где тут колесо»: оно на той же доске, кнопкой слева. Лента + колесо живут на одном объекте-доске, но колесо не воюет за пиксели скана.
- **Перф ленты:** 16 webp-cutout → ленивый/спрайтовый рендер дощечек, иначе скролл-джанк на слабых телефонах.
