# Этап B: заказы через QR-меню

> Продолжение Этапа A (админка). Фундамент (БД, бот, вебхук, деплой) готов.
> Решения владельца (2026-07-04): заказы → чат (по умолчанию личка владельца,
> цель — группа персонала, переключается env `TG_ORDERS_CHAT_ID`); гость вводит
> стол (из QR) + комментарий; весовые — ТОЧНЫЙ вес, шаг 0,5 кг, мин 1 кг.
> Оплаты НЕТ (это Этап 2 дорожной карты) — заказ = заявка персоналу.

## Поток гостя
1. QR на столе → адрес с номером стола (`?t=5`).
2. Меню: у позиций «+ в заказ», счётчик/вес/вариант.
3. Корзина (внизу, sticky): список, кол-во/вес, сумма.
4. «Заказать» → комментарий (опц.) → отправка → «Заказ принят».
5. Заказ прилетает в Telegram-чат персонала: стол, позиции, сумма, комментарий, время.

## Модель позиции в корзине
- **Обычная** (фикс.цена): количество × цена. Селектор кол-ва.
- **Весовая** (`unit === "кг"`): вес (кг, шаг 0,5, мин 1) × цена/кг. Селектор веса.
- **С вариантами** (напр. чай 500/950 мл): выбор варианта (label+цена) + кол-во.
- **Раки** (доска): размер S–XXL + способ (отварные/жареные) + рецепт + вес. Спец-экран.

## Архитектура
- `TG_ORDERS_CHAT_ID` (env; дефолт — первый из `TG_ADMIN_IDS`). `/chatid` в боте
  сообщает id текущего чата (для получения id группы).
- `POST /api/order` (публичный): `{ table, comment, items[], total }` → валидация →
  формат сообщения → отправка в чат через Telegram sendMessage. Rate-limit от спама.
  Цены в сообщении = как у гостя (staff подтверждает; весовые — «~вес», финал по факту).
- Корзина на клиенте (localStorage), стол из query-параметра.
