## Целевая картина (Этап A)

Наталья (и только whitelisted-люди) управляет меню из Telegram-бота:
скрыть/вернуть позицию (стоп-лист), изменить цену/название/описание,
добавить позицию, удалить (мягко, с восстановлением). Сайт меню
подхватывает правки за секунды, оставаясь мгновенно-быстрым для гостей.

## Архитектурные решения (зафиксировано)

- **База:** Neon Postgres (Vercel Marketplace). Схема: `chapters` + `entries`
  (jsonb для `variants`/`footnotes`), поля `is_hidden`, `is_deleted`, `sort_order`.
  `menu.ts` остаётся как сид и офлайн-резерв.
- **Сайт:** уход с `output: "export"` на ISR: страница меню статически
  пререндерена, `revalidateTag('menu')` дёргается ботом после каждой правки.
  Требование: перф не хуже текущего статика (гейт с замером).
- **Бот:** grammY, webhook = route handler в этом же Next-проекте
  (`/api/tg/route.ts`), один деплой на всё. Доступ — whitelist Telegram user id
  через env. Секрет webhook — `secret_token` Telegram.
- **UX бота (согласовано с владельцем 2026-07-04):**
  `/menu` → главы → позиции (скрытые помечены ⛔) → карточка позиции с кнопками:
  **[✏️ Цена] [📝 Текст] [🙈 Скрыть / ♻️ Вернуть] [🗑 Удалить] [◀️ Назад]**;
  в списке позиций главы — кнопка **[➕ Добавить]** (пошаговый диалог:
  название → цена → единица → описание(опц.) → предпросмотр → подтвердить).
  «Удалить» — только с подтверждением и только soft-delete.
- **Фото позиций** — НЕ в Этапе A (нужен пайплайн оптимизации). Отдельным шагом позже.
- **Аудит:** каждая правка пишется строкой в таблицу `audit_log` (кто, что, когда,
  старое→новое) + дублируется сообщением в админ-чат.
